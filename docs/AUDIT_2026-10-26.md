## Verified not to be problems

- Upload pipeline (type sniffing, SVG rejected, 5 MB cap, EXIF stripped, WebP re-encode, random keys) and the path-traversal guard on `/v1/media`: existing tests plus new regression tests (`apps/api/test/catalog-admin.test.ts`).
- Role enforcement for the new endpoints is server-side (`catalog.manage` + `pricing.manage_global`); outlet managers get 403.

## Design system changes

- Tokens (both apps): radii, layered shadows, one easing curve (`--ease-out`) and durations (`--dur-fast/base/slow`). The storefront also gets a `cream` background and brand-50/900.
- Buttons: primary / ghost / accent / danger / tertiary with hover, pressed (scale + inset shadow), `aria-busy` spinner, disabled and a visible focus ring.
- Motion uses only `transform` and `opacity`. Hover lift and image zoom apply only on `(hover: hover) and (pointer: fine)`. 3D tilt and hero parallax (`pointer-motion.tsx`) are driven by CSS variables (no React re-render per pointer move), run only on fine pointers and are disabled under `prefers-reduced-motion`. The one continuous animation is the slow float of the hero logo card (desktop only; stops under reduced motion). No WebGL, no new dependencies.
- Product card: quick add for single-variant in-stock products (repeat taps ignored while a request is in flight, result announced via `role="status"`), an "অপশন দেখুন" link for multi-variant products, an offer badge only when a real compare-at price exists, a stock badge, a shimmer while the image loads and a placeholder on failure.

## Limits

- UI_UX_SPEC asked for flat colours; the hero now has one subtle gradient and layered shapes. Update the spec if this direction is kept.
- SSLCOMMERZ and SMS adapters are still tested only against mocks; no provider sandbox was available.
- OWASP ZAP, manual ASVS review, TalkBack pass and a restore test on a managed database are still outstanding.

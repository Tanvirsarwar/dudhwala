## Verified not to be problems

- Upload pipeline (type sniffing, SVG rejected, 5 MB cap, EXIF stripped, WebP re-encode, random keys) and the path-traversal guard on `/v1/media`: existing tests plus new regression tests (`apps/api/test/catalog-admin.test.ts`).
- Role enforcement for the new endpoints is server-side (`catalog.manage` + `pricing.manage_global`); outlet managers get 403.

## Design system changes

- Tokens (both apps): radii, layered shadows, one easing curve (`--ease-out`) and durations (`--dur-fast/base/slow`). The storefront also gets a `cream` background and brand-50/900.
- Buttons: primary / ghost / accent / danger / tertiary with hover, pressed (scale + inset shadow), `aria-busy` spinner, disabled and a visible focus ring.
- Motion uses only `transform` and `opacity`. Hover lift and image zoom apply only on `(hover: hover) and (pointer: fine)`. 3D tilt and hero parallax (`pointer-motion.tsx`) are driven by CSS variables (no React re-render per pointer move), run only on fine pointers and are disabled under `prefers-reduced-motion`. The one continuous animation is the slow float of the hero logo card (desktop only; stops under reduced motion). No WebGL, no new dependencies.
- Product card: quick add for single-variant in-stock products (repeat taps ignored while a request is in flight, result announced via `role="status"`), an "অপশন দেখুন" link for multi-variant products, an offer badge only when a real compare-at price exists, a stock badge, a shimmer while the image loads and a placeholder on failure.

## Limits

- UI_UX_SPEC asked for flat colours; the hero now has one subtle gradient and layered shapes. Update the spec if this direction is kept.
- SSLCOMMERZ and SMS adapters are still tested only against mocks; no provider sandbox was available.
- OWASP ZAP, manual ASVS review, TalkBack pass and a restore test on a managed database are still outstanding.

## PR review addendum

Found and fixed while reviewing PR #1:

- **Bulk price import silently cleared compare-at prices** when the file had no `compareAtTaka` column (the previous code treated a missing value as "clear"). Now: no column = keep, blank cell = clear, value = set; a kept compare-at that is no longer above the new price is reported as a row error. Audit entries now record before/after compare-at and a summary entry `catalog.bulk_price_import` is written. Regression test added.
- **`NEXT_PUBLIC_MEDIA_ORIGINS` was copied into the CSP unvalidated.** A value containing `;`, a wildcard or a non-https origin could widen the policy. Both Next apps now accept only bare https origins (plain `http://localhost` in development) and fail the build otherwise.
- New E2E check that the production build's CSP does not allow the demo photo host.

Reviewed, no change needed: bulk endpoints require a CSRF token and `catalog.manage` + `pricing.manage_global` on the server (managers get 403, anonymous callers 401/403); CSV export is formula-safe via the shared `toCsv` and audited; import is capped at 500 rows, uses integer poisha through `parseTaka`, and applies in one transaction only when every row is valid. Known limitation: no optimistic-concurrency check, so a price edited by someone else between preview and apply is overwritten (the audit log records both values).

## Staging-readiness pass

- **Dependency advisories (`pnpm audit`, 2026-10-26):** 7 findings (3 high, 2 moderate, 2 low) that did not exist at the earlier audit. Fixed by `pnpm.overrides` in the root `package.json` for the transitive packages `body-parser` (>= 2.4.0), `multer` (>= 2.5.0) and `fast-uri` (>= 3.1.9); API tests and E2E pass on the result. **One high finding remains: `zod` 3.25.76 ("Zod can exhaust memory while validating oversized constraint"; the advisory lists 4.6.6 as the first fixed version).** The API uses zod 3 across all request validation; moving to zod 4 is a breaking migration and was not done here. Request bodies are already capped (JSON 64 kb, urlencoded 8 kb in `bootstrap.ts`), which limits input size, but whether that fully neutralises the advisory was **not assessed**. Decide before production whether to migrate.
- **S3 adapter:** the AWS SDK's default CRC32 checksum headers are now disabled (`WHEN_REQUIRED`) because several S3-compatible providers reject them; covered by `test/s3-media.test.ts`.
- **Cookies/CORS/CSRF** behaviour for staging-shaped settings is now covered by `test/staging-cookies.test.ts`.
- **Database least privilege:** `infra/ops/least-privilege.sql`; the full E2E suite passes with the API connected as the DML-only role.
- **TLS finding:** with pg 8.23.1, `sslmode=require` means verify-full; Supabase's CA must be trusted (see DEPLOY_VERCEL_SUPABASE §2).
